28:T1e18,<h2 id="introduction">Introduction</h2>
<p>Infrastructure automation is a critical aspect of modern system administration. My project focused on using Ansible to automate essential administrative tasks such as:</p>
<ul>
<li>Managing SSH Key Authentication</li>
<li>Creating and Removing Users Securely</li>
<li>Configuring Sudoers for Role-Based Access Control</li>
<li>Monitoring and Logging Sudo Actions</li>
<li>Deploying Security Enhancements (Safe Deletion, Password Policies, etc.)</li>
</ul>
<p>The primary goal was to create an automated, repeatable, and scalable solution for managing user access and securing the infrastructure.</p>
<h2 id="1-ssh-key-management-and-secure-access-automation">1. SSH Key Management and Secure Access Automation</h2>
<p>One of the core challenges in multi-node environments is secure authentication. Instead of relying on password-based access, I automated SSH key generation, distribution, and configuration.</p>
<h3>Generating and Distributing SSH Keys</h3>
<p>Ansible was used to generate SSH keys for different hosts and copy them to the appropriate machines.</p>
<p>Playbook for Generating SSH Keys (Conditional Execution to Avoid Overwriting):</p>
<pre><code class="language-yaml">- name: Generate SSH keys for root if they don’t exist
  hosts: all
  become: false
  tasks:
    - name: Check if root SSH key exists
      stat:
        path: "~/.ssh/id_rsa"
      register: ssh_key_check

    - name: Generate SSH key for root
      shell: ssh-keygen -t rsa -N '' -f ~/.ssh/id_rsa
      when: not ssh_key_check.stat.exists
</code></pre>
<h3>Copying SSH Keys to Ansible Host</h3>
<p>To allow secure, password-less communication between machines, public keys were copied to the Ansible control machine:</p>
<pre><code class="language-yaml">- name: Copy SSH keys to Ansible control machine
  hosts: awsnodes
  become: true
  tasks:
    - name: Fetch public SSH key from nodes
      fetch:
        src: "~/.ssh/id_rsa.pub"
        dest: "/root/awskeys/{{ inventory_hostname }}_id_rsa.pub"
        flat: yes
</code></pre>
<h3>Copying SSH Keys to Target Nodes</h3>
<pre><code class="language-yaml">- name: Copy SSH keys to authorized_keys on target nodes
  hosts: logserver
  become: true
  vars:
    key_dir: /root/awskeys
  tasks:
    - name: Ensure .ssh directory exists
      file:
        path: "/root/.ssh"
        state: directory
        mode: "0700"

    - name: Add public SSH keys
      authorized_key:
        user: "root"
        key: "{{ lookup('file', item) }}"
        state: present
      with_fileglob: "{{ key_dir }}/*_id_rsa.pub"
</code></pre>
<h3>Outcome</h3>
<ul>
<li>Password-less authentication across all servers</li>
<li>Hardened security by eliminating password-based access</li>
<li>Automated onboarding for new machines with SSH authentication</li>
</ul>
<h2 id="2-automated-user-and-sudoers-management">2. Automated User and Sudoers Management</h2>
<p>Managing users manually across multiple servers can lead to inconsistencies and security risks. Ansible was used to automate user creation, privilege assignment, and sudoers configuration.</p>
<h3>Creating Users</h3>
<pre><code class="language-yaml">- name: Create users on all nodes
  hosts: all
  become: true
  vars:
    users:
      - alice
      - bob
      - charlie
  tasks:
    - name: Add users
      user:
        name: "{{ item }}"
        create_home: yes
        state: present
      loop: "{{ users }}"
</code></pre>
<h3>Granting Sudo Privileges</h3>
<p>To enforce role-based access control, users were assigned to the sudoers file with strict validation:</p>
<pre><code class="language-yaml">- name: Configure sudoers for specific users
  hosts: all
  become: true
  tasks:
    - name: Add users to sudoers
      lineinfile:
        path: /etc/sudoers
        state: present
        line: "{{ item }} ALL=(ALL) NOPASSWD: ALL"
        validate: "/usr/sbin/visudo -cf %s"
      loop: "{{ users }}"
</code></pre>
<h3>Outcome</h3>
<ul>
<li>Role-based access management</li>
<li>Automated onboarding &#x26; offboarding of users</li>
<li>Strict sudoers validation to prevent misconfigurations</li>
</ul>
<h2 id="3-monitoring-sudo-commands-and-logging-activity">3. Monitoring Sudo Commands and Logging Activity</h2>
<p>To improve security, all <code>sudo</code> activity needed to be logged and monitored remotely.</p>
<h3>Playbook for Enabling Sudo Logging</h3>
<pre><code class="language-yaml">- name: Configure sudo logging
  hosts: all
  become: true
  tasks:
    - name: Add sudo replay logging
      lineinfile:
        path: /etc/sudoers
        state: present
        insertafter: '^# Defaults.*visiblepw'
        line: |
          Defaults log_output
          Defaults!/usr/bin/sudoreplay !log_output
          Defaults!/sbin/reboot !log_output
</code></pre>
<h3>Automated Log Collection and Sync</h3>
<p>A script was deployed to automatically sync logs from all nodes to a remote monitoring server.</p>
<pre><code class="language-bash">#!/bin/bash
SRC="/var/log/sudo-io/"
DEST_DIR="/root/sudologs/{{ inventory_hostname }}/"
DEST_HOST="root@18.218.206.77"
SSH_PORT=4956

ssh -p "$SSH_PORT" -o StrictHostKeyChecking=no "$DEST_HOST" "mkdir -p $DEST_DIR"
rsync -avz -e "ssh -p $SSH_PORT -o StrictHostKeyChecking=no" "$SRC" "$DEST_HOST:$DEST_DIR"
</code></pre>
<p>A cron job was configured to run this script every 12 hours.</p>
<pre><code class="language-yaml">- name: Schedule sudo log monitoring script
  cron:
    name: "Monitor Sudo Logs"
    minute: "0"
    hour: "*/12"
    job: "/root/monitor_sudo_logs.sh >> /var/log/monitor_sudo_logs.log 2>&#x26;1"
    state: present
</code></pre>
<h3>Outcome</h3>
<ul>
<li>Centralized sudo activity monitoring</li>
<li>Regular log synchronization for auditing</li>
<li>Prevention of privilege escalation attempts</li>
</ul>
<h2 id="4-enhancing-security-with-safe-deletion-policies">4. Enhancing Security with Safe Deletion Policies</h2>
<p>Accidental file deletions can cause irreversible damage. To prevent this, I implemented a safe deletion wrapper script.</p>
<h3>Safe <code>rm</code> Script</h3>
<pre><code class="language-bash">#!/bin/bash
echo "Warning: You are using the 'rm' command which deletes files permanently!"
echo "Files to be deleted: $@"
read -p "Are you sure you want to continue? (y/n) " -n 1 -r
echo
if [[ $REPLY =~ ^[Yy]$ ]]
then
    /bin/rm "$@"
else
    echo "Operation cancelled."
fi
</code></pre>
<h3>Deploying Safe <code>rm</code> Script Using Ansible</h3>
<pre><code class="language-yaml">- name: Deploy safe_rm script
  hosts: all
  become: true
  tasks:
    - name: Copy safe_rm script
      copy:
        src: safe_rm.sh
        dest: /usr/local/bin/safe_rm
        mode: "0755"

    - name: Alias rm to safe_rm
      blockinfile:
        path: /etc/profile
        block: |
          alias rm='safe_rm'
        create: yes
</code></pre>
<h3>Outcome</h3>
<ul>
<li>Prevention of accidental file deletions</li>
<li>Enhanced safety while using <code>rm</code> command</li>
<li>Forced user confirmation before permanent deletions</li>
</ul>
