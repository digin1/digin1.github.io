27:T16e3,<h2 id="the-idea">The idea</h2>
<p>Cortex gives AI coding workflows a persistent layer of project knowledge. Instead of reconstructing conventions, decisions, and past corrections at the start of each conversation, an agent can retrieve relevant context and continue working with it.</p>
<p>The system brings together memory, agent management, skill discovery, and ongoing work tracking. Claude Code hooks connect these capabilities to the session lifecycle, while a local Model Context Protocol (MCP) server makes the underlying tools available to other compatible coding clients.</p>
<h2 id="project-aware-memory">Project-aware memory</h2>
<p>Memories are stored in ChromaDB with types, tags, and project metadata. The recall flow identifies the current project and retrieves relevant knowledge before a prompt is processed. A context-injection path also supplies relevant knowledge when a subagent starts.</p>
<p>Memory types distinguish project decisions, user preferences, feedback, and reference material. This supports a store that can retain both technical context and the corrections that should influence future work.</p>
<p>The learning flow gives the coding agent an opportunity to save useful knowledge as a session concludes. Other hooks support context compaction, session summaries, and cleanup.</p>
<h2 id="hybrid-retrieval">Hybrid retrieval</h2>
<p>Coding context contains both conceptual knowledge and exact identifiers: filenames, flags, commands, and node names. Cortex combines several retrieval signals to handle that mix:</p>
<ol>
<li><strong>Dense retrieval:</strong> ChromaDB searches vector embeddings for semantically related memories.</li>
<li><strong>Keyword retrieval:</strong> BM25 retrieves documents containing matching tokens, including identifiers that semantic search can miss.</li>
<li><strong>Rank fusion:</strong> reciprocal rank fusion combines the candidate lists.</li>
<li><strong>Reranking:</strong> a cross-encoder reorders the fused candidates before the final results are returned.</li>
</ol>
<p>The retrieval code degrades gracefully when individual components are unavailable. Fused results can be used without a reranker, and either dense or keyword retrieval can supply candidates if the other path fails.</p>
<p>Embeddings use <code>Alibaba-NLP/gte-modernbert-base</code>, served through a warm local sidecar to avoid repeatedly loading the model. The embedding integration also provides an in-process fallback using the same model and normalisation settings.</p>
<h2 id="an-agent-fleet-that-can-evolve">An agent fleet that can evolve</h2>
<p>Cortex can propose agents from accumulated project knowledge and recurring patterns in conversations. Usage tracking and evaluation feed a lifecycle that includes creating, updating, and retiring agent definitions.</p>
<p>Agent updates create backups, and retired agents are moved into a separate archive. Project and global scopes allow specialised knowledge to remain close to the work it belongs to.</p>
<p>Skill discovery follows a related pattern: detect the project's technology stack, identify useful capabilities, and generate slash-command skills. Cooldowns, per-run limits, and overwrite protection constrain automated changes.</p>
<h2 id="memories-reminders-and-plans">Memories, reminders, and plans</h2>
<p>Cortex separates three kinds of persistent information:</p>
<p>| Store | Purpose |
|---|---|
| Memories | Facts, preferences, corrections, and reference knowledge |
| Reminders | Individual obligations with due dates, relevance matching, and completion states |
| Plans | Goals and checklists that can progress across multiple sessions |</p>
<p>Keeping these in separate collections prevents knowledge consolidation from merging distinct obligations or plans. Reminders surface within coding sessions through due lists and subject matching. Plans retain checklist progress and distinguish active work from future work.</p>
<p>Reminder delivery happens during a session; it does not run as an external alarm or notification service.</p>
<h2 id="integration-and-operational-controls">Integration and operational controls</h2>
<p>The implementation combines Python modules, Bash hooks, ChromaDB, and an MCP server. Claude Code receives automatic recall and lifecycle integration through its hooks. Other MCP-compatible clients, including Codex CLI and OpenCode, can call the memory, reminder, and plan tools through the same local server; their automation depends on the client's configuration.</p>
<p>The repository documents controls for maintaining the system over time:</p>
<ul>
<li>Audit records for memory operations and archived content for deleted memories.</li>
<li>Duplicate detection, merge tracking, recall statistics, and consolidation.</li>
<li>Stale-path flags that preserve the underlying memory.</li>
<li>Path validation and filename sanitisation for generated agents.</li>
<li>Backups before agent updates and an archive for retired agents.</li>
<li>Cooldowns, process locks, and limits for automated background work.</li>
</ul>
